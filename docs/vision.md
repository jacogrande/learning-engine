# Vision: Agentic Course System

I want to make a custom agentic course system for learning. Here's the process I'm thinking of:

## The Process

1. Have an idea for a thing I want to learn or a subject I want to get better at. Let's say lean methodology in business for this example.
2. I prompt claude code with `/start-course lean methodology in business`
3. Claude asks any clarifying questions about what I mean and the depth I'd like to go on this subject (entry level, expert, professional, etc)
4. Claude spawns subagents and performs some deep research on the topic. It doesn't need to drill down yet, it just needs to be aware of what the main talking points are and develop an understanding of the breadth of the subject.
5. Claude creates a new "Course" in our local system (a git managed, local sqlite or filesystem based, or both approach).
6. I go to our local site and see the course as an option. I open it.
7. Since the course was just generated, the only thing in there is a baseline test. This was generated by claude to see where I'm at with the subject. It should be carefully designed with a mix of open answer questions and multiple choice questions.
8. After submitting the test, Claude assesses where I'm at and then generates a course outline. It should stay out of the weeds and focus on module level knowledge.
9. Each time I "start" a module, Claude should spend some time generating that module. Here, it will spawn more research subagents to investigate and drill down into that module. Here, we'll avoid expanding the scope or breadth of the subject. Instead, we'll drill down on that specific module. We'll find external resources, documents, literature, research, etc.
10. Once subagents have written up documentation, we'll have Claude generate the code for a "module". This will be our custom tech that will support this feature. We'll have the following layout:
    - A sidebar with navigation for the module items + other modules (with a back button to see the whole course outline).
    - A main page view for reading the actual course. This will be generated by claude. It will use html for visualizations, charts, diagrams, links, etc.
    - A right side section for notes. In the main course screen, I can highlight text and an action menu will appear. One of the actions will be "take note". That quote gets added in our note screen and I can add notes about it. I can also do freeform entry. It should be a markdown editor (TipTap?).
11. What does our actual course content contain?
    - Concise, clear english breaking down the topic. It should take the voice of a professor. It should avoid verbosity. It should avoid Claudisms. It should use active voice. It should be inspired by the greats: Hemingway, Steinbeck, etc.
    - Active reading testing: at the end of every section (big or small), there should be a few multiple choice questions / open answer questions ensuring I understand the content. My answers should be sent to claude code and the doc should be updated with messaging on anything I misunderstood or missed.
    - Other learning tactics that we can research for understanding.
12. The actions menu: When hovering over text (or as an ellipses next to section / page headings), we want to show a menu popover with a few actions (like a toolbar). These are the options:
    - **Add to Note.** We explained this above. Take a quote and add it to the notepad.
    - **Drill Down:** This will trigger claude to spawn a research subagent and drill down on the topic (with optional prompt guidance).
    - **Find Additional Reading:** This will trigger claude to spawn a research subagent to find articles, studies, research, and books with additional reading for this feature.
    - **Chat:** This will replace the notes view with a chat view (assigned to the section or selection). Here, the user can chat directly with claude code about the thing highlighted.
13. At the end of each module, we'll ask the user to summarize the module in a rich text editor / give them a custom generated test. Then, we'll start a chat with them based on their answer. What did they miss? What can we push back on? Direct the user towards thinking through the topic themselves. For example, if we'll eventually get to counterexamples or arguments against the topic in the future, can we push the user into coming up with those themselves?
14. Mark that module item as done, and move onto the next item.
15. Once an entire module is done, we should create a summary of their understanding of that module for future module generation to reference.

## Technology Challenges

1. **This all runs locally for this one very specific reason:** user actions need to trigger requests to Claude Code that use their Claude Code account usage. Every time they chat, drill down, ask for a module, etc, Claude Code needs to generate and send output. For things like Modules and drill downs, Claude Code needs to generate new files that we then hot reload into the web app.
2. **Saving things.** When Claude generates output, it needs to be saved. Files need to be created, responses need to be tracked, etc. When the user answers questions, we need to save that. We need to save user notes, interactions, etc, and map them to claude objects like files, responses, chats, drill downs, etc.
